# Explore A · V8 深度与红外领域适配

以 V7 seed 42 的 VideoMAE V2-S 最佳单模型为共同起点。该模型从公开的 Kinetics-710 权重迁移而来，已在比赛训练集上微调。V8 主要回答从这个起点继续适配是否有收益。

把原先四通道的卷积核切分给深度与 IR，各路随后独立通过一个瓶颈 Adapter，再把两路 token 相加送入同一个时空骨干。这里的 token 是两帧内一个空间小块的特征。Adapter 的最后一层从零开始，所以切分前后应得到等价的初始预测。CPU 初始化检查使用一个 16 帧片段与 V7 比较，四个 V8 变体的最大分数差均约为 8.64e-7。

| 组别 | 内容 |
|---|---|
| control | 保留 V7 四通道输入，用 V8 的两轮训练预算做全量续训对照 |
| dual | 深度和 IR 独立投影及 Adapter，全量分层学习率微调 |
| lora | 双路输入和 Adapter，冻结注意力原参数，给查询和数值投影加秩 8 的更新，训练输入层、LoRA、最终归一化和分类头 |
| staged | 第一轮只训练输入层、归一化和分类头，第二轮解冻后四个 Transformer 块 |
| ssl | 沿用 staged，额外先在训练集做一遍无标签的跨模态块均值预测，只更新两个 Adapter 与临时预测头 |

自监督阶段随机选约四分之一时空块，让深度特征预测对应红外块的均值，也让红外特征预测对应深度块的均值。推理只使用动作分类头。staged 与 ssl 的差别是这一额外训练阶段，其余监督训练预算相同。control 和 dual 的输入层学习率也不同，二者比较的是整套输入适配策略。一次短训用来筛选方向，无法分辨不同随机种子的波动或判断架构上限。

每组使用同样的 1995 段训练片段、466 段公开验证片段、16 帧和 192 裁剪缓存。基准种子 42，每批 8 段。每轮只用验证集比较，先按准确率、再按 Macro F1 选择检查点。V8 候选的融合比例固定为 VideoMAE 0.75、R34 0.25，沿用 V7 的比例。选中后用原图逐段复验，并检查离线加载和参数量。以往 V7 融合的公开验证结果是 71.89% / 68.33%。

下列命令从项目根目录执行，以 dual 为例，其他组替换两处名称。缓存、权重和数据使用队内已有的 V7 复现材料。

```powershell
$py = ".\.venv\Scripts\python.exe"
& $py optimized/train_domain_v8.py --cache cache/crop16-192-v3 --initial runs/videomae2_s-v7-20261114/best_ema.pt --output runs/v8-domain-20261122/dual --mode dual --epochs 2
& $py optimized/package_domain_v8.py --runs runs/v8-domain-20261122 --output submission/v8-domain-20261122
```

参考来源：[VideoMAE V2](https://github.com/OpenGVLab/VideoMAEv2) 和 [LoRA 论文](https://arxiv.org/abs/2106.09685)。公共预训练文件、数据及中间缓存沿用 V7 复现包。结果和最终文件的哈希在实验目录和交付包。
